## Multiple packages

The Vuemail repository is a [pnpm monorepo](https://pnpm.io/workspaces), which means it contains
multiple packages.

Because we use pnpm, you will need to use [pnpm](https://pnpm.io/) to install and run each package. If you do not have pnpm installed, follow the [pnpm installation guide](https://pnpm.io/installation):

```bash
npm install -g pnpm
```

Currently, we have the following packages:

- [@vuemaildev/vuemail](https://github.com/psycarlo/vuemail/tree/main/packages/vuemail)
    - The package for our [email CLI](/cli), and for all of our components
- [@vuemaildev/render](https://github.com/psycarlo/vuemail/tree/main/packages/render)
    - The [render](/utilities/render) utility. Can also be imported from `@vuemaildev/vuemail`.
- [@vuemaildev/ui](https://github.com/psycarlo/vuemail/tree/main/packages/ui)
    - The preview app the CLI runs
- [@vuemaildev/editor](https://github.com/psycarlo/vuemail/tree/main/packages/editor)
    - The embeddable [visual editor](/editor/overview) for composing emails
- [@vuemaildev/nuxt](https://github.com/psycarlo/vuemail/tree/main/packages/nuxt)
    - The [Nuxt module](/getting-started/nuxt) that lets server routes render emails
- [create-vuemail](https://github.com/psycarlo/vuemail/tree/main/packages/create-vuemail)
    - Used for our [automatic setup](/getting-started/automatic-setup)

### Turborepo

We encourage using [turborepo](https://turbo.build/repo) to manage the packages.

It's often helpful to [install Turborepo globally](https://turbo.build/repo/docs/installing) to make it easier to run commands in any of the repositories. With a global installation, running `turbo build` in any of the packages will build both the package
you are on as well as the dependent packages. The global installation handles [version mismatching as well](https://turbo.build/repo/docs/installing#install-per-repository).

### The Vuemail CLI

The CLI is built using [commander](https://www.npmjs.com/package/commander), a CLI builder for node. It handles
parsing of command line arguments and ensuring that the syntax for the command is as expected.

The `dev`, `build`, `start` and `export` commands all depend on the user first installing `@vuemaildev/ui`,
in the same version as `@vuemaildev/vuemail`. The CLI loads it from the user's project, and when it's missing or its
version doesn't match, it asks to install it, using [nypm](https://www.npmjs.com/package/nypm) to add it
with the user's package manager.

### The Preview Server

The Preview Server, `@vuemaildev/ui`, has two sides:

- `src/node` is the server the CLI starts. It compiles the user's emails with [Vite](https://vite.dev) and
  `@vitejs/plugin-vue`, loading them with Vite's server-side module loader, and renders them with the
  [render](/utilities/render) utility from the user's own `@vuemaildev/vuemail`. Vite's file watcher detects changes to
  the files the emails depend on, which the server sends to the browser as server-sent events.
- `src/client` is the preview app itself, a Vue 3 single page app built with Vite, [vue-router](https://router.vuejs.org),
  [reka-ui](https://reka-ui.com) and Tailwind CSS 4.

As changes are sent to the preview app, the preview updates automatically. `email build` renders every
email ahead of time instead, into a static website.

## Testing

For testing, we use [vitest](https://vitest.dev/). We prefer to define globals, and run tests under the `happy-dom`
environment for the code that runs in the browser, like the preview app and the editor, and under `node` for the rest.

We do not strictly enforce testing coverage, but encourage it.

For help testing, see our [Development workflow guide](/contributing/development-workflow/2-running-tests).

<Note>
The tests of `@vuemaildev/nuxt` build and start real Nuxt apps, so they take longer than the others.
</Note>

## Linting

We use [biomejs](https://biomejs.dev/) for linting and formatting. Both the linting and formatting are ensured by our GitHub CI so make sure you lint and format your code (`pnpm lint:fix`) before opening a PR or asking for a review on it.

For help linting and formatting, see our [Development workflow guide on linting](/contributing/development-workflow/3-linting).

## Building

We use [tsdown](https://tsdown.dev) to build the packages. The preview app of `@vuemaildev/ui` is built with
[Vite](https://vite.dev). For help building packages, see our [Development workflow guide](/contributing/development-workflow/4-building).

<Note>
Building each package runs `tsdown` with the settings in its `tsdown.config.ts`. `@vuemaildev/vuemail` and `@vuemaildev/render` are built as both ESM and CJS,
along with the type definitions exported from the entry point, `src/index.ts`, without bundling `vue`, which can cause issues.
</Note>

### Why build before publishing?

We build the packages before publishing for a few reasons:

1. All the exported types can be imported from the same place the JavaScript is imported
2. We have proper [CommonJS](https://nodejs.org/docs/latest/api/modules.html#modules-commonjs-modules)
and [ES Modules](https://nodejs.org/api/esm.html#modules-ecmascript-modules) support
3. Code that isn't exported is not published or downloaded
